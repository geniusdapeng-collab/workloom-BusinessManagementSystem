01 / CUSTOMER JOURNEYS

一条业务链，每个承诺都有前置条件。

把口头交接变成对象、阶段与证据。客户需求缺信息时先补问，设备组合缺依据时暂停，报价未批准时留在草稿。

◎

ACQUISITION

登记渠道归因、装修阶段、预算和用途授权；宿主模型核对资格，形成有依据的内容草稿与拟议体验计划。外发、邀约送达和客户确认分别保留状态。

02 / FOUR CONNECTED LAYERS

看得懂业务，也看得见机制。

四层使用同一套业务名称、权限与证据口径。岗位规程、领取任务、浏览器表单和账本回执可以相互对照。

01

经营场景与客户旅程

JOURNEY

店主看目标和待决事项；顾问看客户与体验；工程团队看勘测、方案和里程碑；售后团队看故障、现场证据与回访。

02

能力与业务对象

CAPABILITY

19 类业务对象共享 39 项操作。CLI、MCP 与本地 HTTP 都经过同一业务网关，校验归属、授权、兼容证据、审批摘要与阶段依赖。

03

数字员工与技能

WORKFORCE

20 个岗位各有责任归属，35 个技能带完整规程。五类工作流覆盖获客、交付、售后、经营诊断与任意岗位准备任务。

04

宿主模型与账本

EXECUTION

Codex、千问办公、WorkBuddy 通过 stdio MCP 使用当前宿主模型。运行时只调度和校验，SQLite 同步保存对象、幂等回执与哈希事件链。

◇

人工权限与承诺

HUMAN DECISION

报价审批绑定内容摘要和有效期。浏览器店主授权需要真实终端确认；MCP 固定 Agent 身份，模型不能自行批准报价或登记现场验收。

↯

可见的失败路径

RECOVERY

过期租约可以恢复领取，失败保留历史并有限重试；对象版本变化、数据损坏或前置证据缺失会阻断提交，不以编造数据推进。

03 / RUN LOCALLY

从沙箱开始，用当前工作台模型推进。

独立经营入口需要 Node.js 24 或更高版本。先运行 doctor，再显式初始化合成数据；CLI 和 MCP 的业务运行时无需新增模型 API 密钥。

01

取回源码

克隆公开 CNB 仓库，在仓库根目录检查运行环境。先读 AI 工作台接入文档 与仓库 README。

源码交付采用 Apache-2.0。桌面签名发行状态以仓库正式发布为准。
02

启动本地工作台

明确选择沙箱与合成样本，浏览器工作台显示目标、审批、任务和账本。默认服务仅监听本机回环地址。

模拟门店、设备、客户和证据均有 synthetic 标记，不可作为商业案例使用。
03

连接宿主并派活

setup 为支持的宿主生成项目配置。宿主模型领取任务、按 schema 提交，再读取目标报告；遇到审批与现场证据时交付待办。

模型执行需要运行中的宿主会话。后台 tick 负责调度，关闭宿主后不会继续推理。
# 在 Node.js 24+ 环境执行
git clone https://cnb.cool/workloom-ai/workloom-BusinessManagementSystem.git
cd workloom-BusinessManagementSystem
node scripts/business-management.mjs doctor
node scripts/business-management.mjs init --demo
node scripts/business-management.mjs setup --client all
node scripts/business-management.mjs serve
# 浏览器打开 http://127.0.0.1:9393
Codex 的真实宿主执行证据随仓库验收资料提供；千问办公和 WorkBuddy 的配置按官方文档接入，具体客户端真机结果须独立验收。完整继承平台的 PostgreSQL 与三端构建使用仓库对应运行链。
04 / EVIDENCE & AUTHORITY

本地结果能复查，外部动作有明确边界。

人类拥有报价承诺、客户授权和现场责任。设备兼容性由具体型号、固件、网关和生态条件决定，不能由协议标签或模型印象代替。

● 当前连接器状态与记录含义

发布、消息、付款和真实设备控制连接器均未启用（disabled）。本地回执证明 SQLite 提交成功；externalVerified=false。live 表示真实数据目录，仍需人类核实来源和现场事实。

授权独立留痕咨询、预约、营销与售后分别记录用途，撤回后对应工作暂停。
兼容证据绑定版本具体 SKU、固件与组合证据缺失或过期时，方案不能推进。
审批固定内容毛利和折扣红线硬阻断；批准不能绕过经营阈值。
现场步骤顺序合同、采购、安装、调试、验收由有权限的人类登记。
系统会自动替门店发视频、联系客户或控制设备吗？

当前会生成本地内容草稿、拍摄计划、预约计划和处置方案。外部发布、消息、支付和设备控制未启用；审批通过也不能解锁。接入真实平台需单独实现授权、凭据托管、平台权限和外部回执验证。

35 个技能都已经能执行吗？

全部技能都能通过 employee-work 被领取并提交结构化准备产物；固定业务工作流还有确定性对象写入与依赖推进。视频岗位交付拍摄与剪辑说明，财务岗位交付核对计划；视频渲染、付款与真实账务处理不在当前已启用执行范围。

如何从沙箱迁移到真实门店？

创建独立 live 数据目录与工作区，登记门店规则、实际 SKU 版本和有来源的客户/现场证据。合成记录不能变成真实口径。店主在真实交互终端授权人工会话，核实审批摘要、合同和现场材料。

行业依据读取日期记录在仓库来源清单。官方资料证明通用机制，不证明某家门店已具备真实账号、权限、设备或案例。
