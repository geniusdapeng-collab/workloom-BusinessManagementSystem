# 把 AI 经营系统配置为自己的全屋智能门店

本产品默认已经装配全屋智能行业包。你要配置的是自己的门店范围、产品依据、客户流程和人工责任，随后用当前 AI 工作台模型执行任务。默认的蜀光智家 · 成都高新体验店是演练背景。

## 先用成都模拟门店走通

按 [AI工作台接入](AI-WORKBENCH.md)执行 `init --demo`，在sandbox看完整门店背景、产品、各阶段客户、点位与工程记录。让当前宿主实际推进AI任务，观察补信息、待审批、待证据和失败恢复。历史导入有明确synthetic来源，不模拟店主真实批准、不声称真实资金或设备结果。

这条路线的验收标准是能追到每个步骤的输入、责任人、输出与未完成原因。指标多少来自实际查询，不用一张漂亮页面代表经营成功。

## 正式门店配置六件事

| 配置 | 需要准备什么 | AI怎样使用 | 验收时看什么 |
| --- | --- | --- | --- |
| 门店范围 | 名称、城市、服务区域、财务底线、独立数据范围 | 判断服务匹配和报价政策 | 没有把synthetic导入live；范围与底线正确 |
| 产品资料 | 精确型号、固件、类别、成本/售价、厂家安装要求、证据期限 | 准备体验、BOM与兼容检查 | 同协议不当兼容依据；真实价格由门店提供 |
| 空间与场景 | 房间、勘测、回路、网络、点位与生活场景 | 组织中控、照明、窗帘和自动化体验 | 每个场景能追到空间、设备与条件 |
| 来源与客户 | 渠道、合作来源、当前信息、联系引用、用途授权 | 线索完善、销售准备与邀约 | 未知保留未知，客户陈述有来源，冲突可追查 |
| 人员与分工 | 人类负责人、已安装数字岗位、交接和现场责任 | 生成岗位准备任务、下步协作与待决包 | 真实人员负责签约、现场、客户确认与安全 |
| 目标与复盘 | 可计量目标、现有对象、截止时间和约束 | 数字总经理诊断、拆解并汇报 | 指标用当前账本，待决与外部缺口分别陈述 |

## 华为与 Aqara 资料怎样进入经营

[行业背景资料](../bundles/smart-home/library/industry-context.json)保存官方引用和门店采用的体验思路。华为资料帮助组织空间、主机、中控、子系统和服务流程；Aqara资料帮助理解网关、传感、自动化与生态条件。

参考品牌是知识输入。蜀光智家不是品牌授权经销店，合成SKU与价格不代表真实厂家目录。厂家网页不能自动证明当前型号、固件、安装条件或某个跨品牌组合兼容；真实经营需要门店自己的精确证据记录。业务流程仍由目标、数字员工、确定性校验、人类审批和现场证据推进。

## 开始自己的 live 范围

使用独立目录、tenant和workspace。先登记门店与实际产品，再接入客户来源、用途授权和现场资料。真实联系方式保留在受控存储，业务对象保存引用；不要把客户原始资料或账号凭据提交公开仓库。

配置不等于已经完成真实经营。检查草稿、拟议预约、待审批、已登记现场和外部核验状态；只有对应证据成立才能使用相应成功口径。发布、消息、资金和设备控制连接器当前为disabled，人类审批也不会自动开启。

## 接入检查单

- [ ] Node环境与doctor通过，浏览器能读取当前工作区。
- [ ] 沙箱演练与真实数据使用不同范围，来源标识可见。
- [ ] 门店服务区域、毛利/折扣底线由负责人核实。
- [ ] SKU、安装与精确兼容证据有型号、版本、期限和来源。
- [ ] 残缺线索能保存，客户未知字段、联系引用和授权各自明确。
- [ ] 至少演练线索接续、方案工程交接、店长复盘三个场景。
- [ ] 当前宿主实际领取并提交任务；审批和现场缺口能留下待办。
- [ ] 团队知道本地回执、模拟历史、AI准备与真实外部结果的区别。
