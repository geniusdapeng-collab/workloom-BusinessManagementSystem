# 蜀光智家 · 成都高新体验店｜AI经营实战手册

本手册把系统当作一家成都全屋智能门店来使用。蜀光智家是虚构品牌；产品参考有官方来源，门店SKU、定价、客户、楼盘关联、渠道伙伴、交易与工程均为合成演练。它不是华为或Aqara授权门店，也不提供真实客户联系方式。

## 门店经营主线

门店通过设计师、装修公司、物业、异业合作、转介绍、到店和线上内容发现需求，先判断服务范围与装修时机，再用回家、观影、起夜、离家等生活场景组织体验。中控、网关、灯光、开关、窗帘与传感产品进入客户资料、勘测、点位和BOM；工程交接与售后沿同一业务对象接续。

AI的工作是读取目标和记录、执行岗位规程、准备问题与话术、形成设计/施工/经营方案并提交结构化产物。确定性内核检查范围、schema、版本、租约、兼容、价格与前置条件；有权限的人确认客户授权、价格承诺、签约和现场结果。

## 开始前看清三种来源

| 页面里的内容 | 怎样产生 | 能证明什么 |
| --- | --- | --- |
| 行业背景 | 从官方资料提炼产品与服务知识，保存引用 | 参考知识及其来源；不能证明门店获得品牌授权 |
| 模拟历史 | `init --demo`导入已封印的sandbox场景，带dataset/version/digest与synthetic-history-import来源 | 可以复演各阶段的业务状态；不代表真实人审、客户签字、资金或AI刚执行 |
| 本次宿主AI产物 | 当前AI工作台实际claim、理解、生成并submit | 本次本地模型准备或领域产物；外部完成还需要真实回执 |

历史导入不把模型任务标为已执行，任务仍需实际领取。所有演练数据留在sandbox；live拒绝合成历史与合成证据。不要把模拟案例展示为真实安装案例。

## 启动与检查

在仓库根目录按[接入文档](AI-WORKBENCH.md)运行：

```bash
node scripts/business-management.mjs doctor
node scripts/business-management.mjs init --demo
node scripts/business-management.mjs setup --client all
node scripts/business-management.mjs serve
```

打开 `http://127.0.0.1:9393`，检查当前范围为sandbox，门店为蜀光智家成都演练背景。再在已连接本仓的当前AI工作台读取能力目录、行业背景、场景和任务：

```bash
node scripts/business-management.mjs catalog
node scripts/business-management.mjs call industry.context
node scripts/business-management.mjs call scenario.list
node scripts/business-management.mjs call task.list
node scripts/business-management.mjs call ledger.verify
```

先读实际对象和schema再写。CLI `describe <operation>`读取准确字段；普通`call`与MCP固定agent，历史导入有专用沙箱operator入口，人工决断与现场记录走人类确认通道。

## 场景一：设计师递来一条只有称呼的线索

**使用者**：渠道负责人、顾问、线索完善员。**要解决的问题**：合作来源能追到人，但客户信息不完整，顾问不知道下一步问什么。

1. 查看模拟线索里的原始来源、称呼、已有联系引用、楼盘和需求。保持已有字段，未知不填假值；一个线索不能因为没有手机和全名就被抛弃。
2. 让`prospecting-specialist`的`source-lead-intake`准备来源接续与服务匹配；让`lead-enrichment-specialist`的`lead-profile-enrichment`列出优先问题、来源、冲突和联系边界。
3. AI用`lead.enrich`的`model-proposal`来源保存待确认草案，不改变客户事实。顾问在相应用途授权内核对后，经人类确认通道用当前版本接续已确认字段；`customer.upsert`同样需要咨询许可和人类确认，才能建立或完善客户资料。不能覆盖另一人刚核对的信息。
4. 客户资料可交接后，让`customer-handoff-check`核对残留缺口。预算或装修状态未知时先补资料；资格工作流的completed并不保证客户qualified。
5. 让`appointment-coordinator`的`appointment-coordination`准备到店时间和生活场景。人类联系客户并登记确认，外部消息不会由本地连接器自动发出。

**完成判据**：原线索和来源仍在，字段更新有新版本；客户资料能追到线索；问题与授权缺口有明确下一步；预约计划和客户确认口径分开。**错误路径**：无授权、版本冲突、不可用联系引用、服务不匹配时保留原因并停在相应待办。

## 场景二：客户到店，要一套中控与照明方案

**使用者**：顾问、销售助理、方案设计师、勘测与工程人员。**要解决的问题**：客户关心体验，店员容易直接报价，现场条件还没核对。

1. `sales-assistant`使用`sales-meeting-prep`读取客户资料和已知需求，准备场景路线、产品差异、待澄清问题与不可承诺事项。
2. `sales-coach`使用`sales-coaching`练习“已经装修如何做”“为什么要勘测”“设备生态和断网条件”等问答；只用合成角色，保存练习改进点。
3. 现场人员记录勘测，核对房间、零线、回路、负载、网络和设备安装条件。不能把参考户型当作已经测量的客户现场。
4. 用`pointPlan.record`登记分房间尺寸与点位；用当前设备版本与兼容证据建立`solution.build`。缺兼容或网络/电气条件时停下补证据，不能靠同协议推断全屋互通。
5. `design.record`连接当前客户、勘测、点位与已验证方案，核对每个房间/SKU设备点的准确数量，并逐场景填写客户价值、回退和测试方法；再计算`quote.create`，`construction.record`按准确BOM形成施工准备。图形只是登记的设计输入。
6. `contract.create`可基于合规报价草案准备合同；`contract.request_approval`必须已有有效报价批准。店主分别核对报价与合同摘要，真实签约再由人类通过`contract.record_signing`登记客户证据。新版点位、资料或方案会使旧引用失效，需重做对应修订。
7. 按采购到货、安装、逐场景调试、客户培训与控制权移交、客户验收推进。每个现场阶段都有前置，未闭问题不提前算验收完成。

**完成判据**：客户、勘测、点位、设计、BOM、报价、施工方案、合同与项目关系可读回；价格可复算；审批绑定当前摘要；现场步骤和未闭事项可追溯。**错误路径**：兼容过期、SKU变更、点位越界或设备点数量不符、财务底线、合同范围变更、漏调试场景都需修正后重试。

## 场景三：店长要知道明天先做哪几件事

**使用者**：店长、门店经营助理、店长AI助理与数字总经理。**要解决的问题**：客户与项目进度很多，容易只看总数，遗漏缺字段、审批和现场依赖。

1. 读取当前门店目标、全部相关业务记录和任务。列表分页与快照items不是全量统计，指标以运行时实测口径为准。
2. `business-operations-assistant`使用`operations-daily-control`，把新增、缺口、冲突、等待与失败列为可接续事项；`business-data-reconciliation`对照模拟交易与业务记录查差异。
3. `store-manager-assistant`使用`store-shift-coordination`，准备下一班客户接待、现场依赖和未决清单；`store-resource-brief`核对现有资源记录并标明未知。
4. 数字总经理通过`management-loop`核对目标指标、拆成岗位任务。每项任务引用当前对象与责任技能；缺先决客户、勘测或工单的子目标留在waiting-input。
5. 老板审核待决包，通过`goal.instruct`调整目标或暂停。AI准备报告中列出的nextActions是建议，只有实际创建并执行的任务才能算已排队或完成。

**完成判据**：诊断值匹配当前账本，明日事项能定位业务对象、责任岗位和验证条件；审批与现场缺口明确；模拟历史、本次AI产物、本地记录和真实外部结果分别陈述。**错误路径**：资料版本改变、读取失败、目标暂停/过期、任务租约失效时保留状态并恢复，不能继续报旧数。

## 每班交接模板

可让当前AI工作台按以下结构生成本地准备包：

- 对象：客户/线索/项目/工单的现有ID与当前版本。
- 已知：客户陈述、来源、用途授权、现场或厂家证据。
- 已完成：实际记录与对应回执；模拟历史另标来源。
- 待补：信息、证据、审批、材料、人员、客户确认与期限。
- 下步：责任岗位、具体动作、需要人类决定的内容与成功判据。
- 风险：价格与范围变化、版本过期、施工条件、安全或隐私事项。

## 产品体验如何组织

先问客户希望哪个生活动作变简单，再决定需要哪些设备和条件。中控负责可见的入口与场景选择，照明与开关决定房间使用，窗帘与环境设备结合空间和时机，传感器提供条件输入。所有真实产品陈述都追到[官方行业背景](../bundles/smart-home/library/industry-context.json)或当前SKU证据；不能用模拟价格、模拟兼容或模拟设备效果回答客户实盘问题。

## 本阶段边界

P0是可接续线索与客户资料、销售准备、勘测点位设计、报价施工合同与工程证据；P1是岗位协作、日常复盘、售后与经营对账；P2是独立规划的真实连接器、远程身份、同步与长期性能验证。发布、客户消息、资金和设备控制连接器当前disabled。人类审批不会把缺失连接器解锁，现场与资金结果也不会由一个本地SQLite提交自动成立。

技术字段、权限、错误与恢复见[业务实现矩阵](SMART-HOME-BUSINESS-MATRIX.md)；逐步客户旅程见[新客户接入流程](02-新客户首次接入完整流程.md)；店长日常使用见[店长指南](01-门店店长使用指南.md)。
